## 3. Доработка индивидуального проекта

Консольное приложение из ПР3 дополнено веб-интерфейсом на Django 5.2.
Проект продолжен в том же репозитории: консольная версия (`main.py`),
классы предметной области (пакет `models/`), JSON-хранилище
(`storage.py`, `data/`) и тесты сохранены и продолжают работать.

**Django-проект:** `boardgame_finder` (создан командой
`django-admin startproject boardgame_finder .` в корне репозитория).
В `settings.py` зарегистрированы приложения, заданы
`LANGUAGE_CODE = "ru-RU"`, `TIME_ZONE = "Europe/Moscow"`,
`ALLOWED_HOSTS` и путь к JSON-данным `DATA_DIR`.

**Django-приложения:**

| Приложение | Назначение |
|---|---|
| `homepage` | главная страница, общий HTML-каркас `page()`, обработчик 404 |
| `games` | каталог настольных игр (сущность `Game`) |
| `gamerequests` | заявки на поиск игроков (сущность `GameRequest`) и их участники |

Отдельное приложение для игроков не создавалось: в Django есть встроенная
модель пользователя, работа с пользователями будет добавлена позже.

**Реализованные URL и страницы:**

| URL | view-функция | Содержимое |
|---|---|---|
| `/` | `homepage.views.index` | описание сервиса, кнопки перехода к разделам |
| `/games/` | `games.views.games` | список игр из `data/games.json` |
| `/games/<int:game_id>/` | `games.views.game_detail` | игра, число игроков, число открытых заявок |
| `/requests/` | `gamerequests.views.game_requests` | список заявок со статусом «открыта / закрыта» |
| `/requests/<int:request_id>/` | `gamerequests.views.request_detail` | игра, автор, встреча, свободные места, участники |

**Краткое описание выполненной работы:**
- маршрутизация разделена на два уровня: корневой
  `boardgame_finder/urls.py` подключает `urls.py` приложений через
  `include()`; в динамических адресах используется конвертер `<int:...>`;
- view-функции загружают данные средствами ПР3 (`load_games()`,
  `load_users()`, `load_requests()`, `load_joins()`), находят объект по
  идентификатору (`find_game_by_id()`, `find_request_by_id()`) и
  формируют `HttpResponse`;
- HTML-страницы собираются общей функцией `page(title, content)`:
  кодировка, заголовок вкладки, метатег `viewport`, Bootstrap 5.3 через
  CDN и навигация; оформление — классы Bootstrap (`card`, `list-group`,
  `badge`, `btn`);
- если игра или заявка не найдена, возвращается страница с сообщением и
  кодом 404; для несуществующих адресов подключён собственный обработчик
  `handler404 = "homepage.views.page_not_found"` (проверен при
  `DEBUG = False`);
- связи объектов ПР3 используются в веб-интерфейсе: на странице заявки
  выводятся `game_request.game.title`, `game_request.author.name`,
  `game_request.meeting.place` и участники из `join.user.name`;
- добавлены тесты веб-страниц `tests/test_web.py` (тестовый клиент
  Django): статусы 200 и 404, отображение данных;
- в `requirements.txt` добавлена зависимость `Django==5.2.*`,
  README.md дополнен описанием веб-части.

## 4. Результат работы

В результате выполнения ПР5:
- создан Django-проект `boardgame_finder` и три Django-приложения,
  подключённые к проекту;
- настроена двухуровневая маршрутизация URL с динамическими адресами;
- реализованы view-функции и обработка ошибки 404;
- создан веб-интерфейс из пяти страниц с навигацией между ними;
- использованы HTML и Bootstrap 5.3;
- сохранена предметная область индивидуального проекта: страницы
  строятся по объектам `Game`, `User`, `Meeting`, `GameRequest`, `Join`
  из JSON-хранилища;
- выполнены проверки: `python manage.py check` — без замечаний,
  `pytest` — 38 тестов пройдено, `flake8` — без замечаний;
- результат зафиксирован в Git коммитами
  `PR5: Подготовка проекта к переходу на Django` и
  `PR5: add Django project and web pages`.

## 5. Вывод

В ходе ПР5 изучены назначение и структура Django, цикл обработки
HTTP-запроса «URL → view → response», маршрутизация и основы HTML, CSS и
Bootstrap. Консольный проект «Сервис поиска игроков для настольных игр»
получил веб-интерфейс, который использует существующую объектную модель
и JSON-хранилище, не дублируя предметную логику. Проект подготовлен к
переходу на шаблоны Django и в дальнейшем — на Django ORM.
