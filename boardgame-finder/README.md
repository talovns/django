# Сервис поиска игроков для настольных игр

## Назначение

Приложение помогает любителям настольных игр находить компанию.
Игрок создаёт заявку на игру, указывает, сколько нужно участников, и
назначает встречу: дату, город и место. Другие игроки присоединяются к
заявке, пока в ней есть свободные места.

Консольная версия приложения (ПР1–ПР3) дополнена веб-интерфейсом на
Django (ПР5), страницы которого формируются шаблонами Django (ПР6).

## Используемые технологии

- Python 3;
- Django 5.2 – веб-фреймворк;
- Django Template Language (DTL) – шаблоны страниц;
- HTML, CSS, JavaScript – разметка, собственное оформление и поведение;
- Bootstrap 5.3 – базовая вёрстка;
- JSON – хранение данных;
- pytest – автоматизированные тесты;
- flake8, mypy, pylint – проверка качества кода.

## Целевая аудитория

Любители настольных игр, которым не хватает постоянной компании:
студенты, участники клубов настольных игр, новые жители города.

## Предметная область

Пользователь создаёт заявку под конкретную игру. Заявка включает встречу,
на которой игроки соберутся. Другие пользователи присоединяются к заявке.
В заявке не может быть больше участников, чем нужно по заявке. Один игрок
не может дважды присоединиться к одной заявке. Отменённое участие
освобождает место, но остаётся в истории.

## Основные сущности (классы)

### Game – игра (`models/games.py`)
- атрибуты: `id`, `title`, `min_players`, `max_players`;
- методы: `supports_players()` – подходит ли игра для указанного числа
  игроков; `from_data()` (`@classmethod`) – создание из данных JSON;
  `__str__()`.

### User – игрок (`models/users.py`)
- атрибуты: `id`, `name`, `city`;
- методы: `from_data()` (`@classmethod`), `__str__()`.

### Meeting – встреча (`models/meetings.py`)
- атрибуты: `meeting_date`, `city`, `place`;
- методы: `from_data()` (`@classmethod`), `__str__()`.

### GameRequest – заявка (`models/game_requests.py`)
- атрибуты: `id`, `game` (объект `Game`), `author` (объект `User`),
  `players_needed`, `meeting` (объект `Meeting`), `players_joined`;
- методы: `free_slots()` – количество свободных мест, `add_player()`,
  `remove_player()`, `__str__()`;
- свойства (`@property`): `players_joined` (только чтение), `is_open`.

### Join – участие игрока в заявке (`models/joins.py`)
- атрибуты: `id`, `request` (объект `GameRequest`), `user` (объект `User`),
  `is_cancelled`;
- методы: `cancel()` – отмена участия, `__str__()`.

## Взаимодействие объектов

```text
GameRequest
├── game    → Game
├── author  → User
└── meeting → Meeting   (встреча входит в заявку)

Join
├── request → GameRequest
└── user    → User
```

`Join` хранит ссылки на сами объекты, поэтому данные доступны напрямую:
`join.request.game.title`, `join.user.name`, `request.meeting.place`.
При записи игрока в заявку `create_join()` вызывает `request.add_player()`,
при отмене `join.cancel()` вызывает `request.remove_player()`.

## Веб-интерфейс (Django)

Django-проект `boardgame_finder` содержит три приложения:

| Приложение     | Отвечает за                                  |
|----------------|----------------------------------------------|
| `homepage`     | главная страница, общий HTML-каркас, 404     |
| `games`        | каталог настольных игр                       |
| `gamerequests` | заявки на поиск игроков и их участники       |

Отдельное приложение для игроков не создаётся: в Django уже есть
встроенная модель пользователя (`django.contrib.auth`), работа с
пользователями будет добавлена в теме аутентификации.

### Страницы

| URL                          | view-функция                    | Содержимое                                  |
|------------------------------|---------------------------------|---------------------------------------------|
| `/`                          | `homepage.views.index`          | описание сервиса и навигация                |
| `/games/`                    | `games.views.games`             | список игр из `data/games.json`             |
| `/games/<int:game_id>/`      | `games.views.game_detail`       | игра и число открытых заявок на неё         |
| `/requests/`                 | `gamerequests.views.game_requests` | список заявок со статусом                |
| `/requests/<int:request_id>/`| `gamerequests.views.request_detail` | игра, автор, встреча, места, участники  |

Если игра или заявка с указанным идентификатором не найдена, страница
возвращает код 404, а сообщение выводит шаблон через `{% if %}`. Для
адресов, которым не нашлось маршрута, при `DEBUG = False` показывается
собственная страница `homepage/404.html` (обработчик `page_not_found`,
подключён через `handler404`).

Маршрутизация двухуровневая: `boardgame_finder/urls.py` подключает
`urls.py` приложений через `include()`. У каждого приложения своё
пространство имён (`app_name`), поэтому маршруты называются
`homepage:index`, `games:list`, `games:detail`, `gamerequests:list`,
`gamerequests:detail`.

## Шаблоны Django

Представления не формируют HTML: они загружают объекты из JSON,
складывают их в контекст и вызывают `render()`. Функция `page()` из ПР5
удалена.

```text
HTTP-запрос → urls.py → view → context → шаблон → HTML → HTTP-ответ
```

### Структура шаблонов

```text
templates/                       — шаблоны уровня проекта (DIRS)
├── base.html                    — общий каркас: head, шапка, main, подвал
└── includes/navigation.html     — навигация
homepage/templates/homepage/
├── index.html                   — главная
└── 404.html                     — страница «не найдено»
games/templates/games/
├── game_list.html               — список игр
├── game_detail.html             — игра и открытые заявки на неё
└── includes/game_card.html      — карточка одной игры
gamerequests/templates/gamerequests/
├── request_list.html            — список заявок
├── request_detail.html          — заявка, встреча, участники
└── includes/request_status.html — бейдж «Открыта / Закрыта»
```

### Используемые возможности DTL

- наследование: каждая страница начинается с `{% extends "base.html" %}`
  и переопределяет `{% block title %}` и `{% block content %}`;
- включаемые шаблоны: навигация, карточка игры и статус заявки
  подключаются через `{% include %}`; статус заявки используется в трёх
  местах — в списке заявок, на странице заявки и на странице игры;
- контекст: например, `{"games": games_list}` → `{% for game in games %}`;
  для заявок используются имена `game_request` / `game_requests`, чтобы
  не перекрыть переменную `request` (HTTP-запрос);
- циклы с `{% empty %}` для пустых коллекций, условия `{% if %}` для
  статуса заявки и для страниц «не найдено»;
- ссылки только через `{% url %}`, например
  `{% url 'games:detail' game.id %}`;
- фильтры: `length` (число игр, заявок, участников),
  `default` (название игры, место встречи),
  `date:"d.m.Y"` (дата встречи — объект `date`).

### Статические файлы

Находятся в `homepage/static/homepage/` и подключаются в `base.html`
через `{% load static %}` и `{% static %}`:

- `css/style.css` — собственное оформление: шапка, навигация, карточки
  игр и заявок, бейдж статуса, подвал;
- `js/main.js` — текущий год в подвале и подсветка активного пункта меню;
- `img/logo.svg` — логотип (игральный кубик) в шапке.

## Хранение данных

Данные хранятся в JSON в каталоге `data/` (путь задан в
`settings.DATA_DIR`). При загрузке они превращаются в объекты, при
сохранении — обратно в словари. Вместо связанных объектов в JSON
записываются их идентификаторы (`game_id`, `author_id`, `request_id`,
`user_id`), а встреча хранится вложенным объектом внутри заявки.
Django ORM, база данных и формы пока не используются — это задачи
следующих практических работ.

pip install -r requirements.txt

## Запуск

Веб-версия:

```
python manage.py migrate
python manage.py runserver
```

После запуска открыть http://127.0.0.1:8000/.

Консольная версия:

```
python main.py
```
