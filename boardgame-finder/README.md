# Сервис поиска игроков для настольных игр

## Назначение

Консольное приложение помогает любителям настольных игр находить компанию.
Игрок создаёт заявку на игру, указывает, сколько нужно участников, и
назначает встречу: дату, город и место. Другие игроки присоединяются к
заявке, пока в ней есть свободные места.

## Целевая аудитория

Любители настольных игр, которым не хватает постоянной компании:
студенты, участники клубов настольных игр, новые жители города.

## Предметная область

Пользователь создаёт заявку под конкретную игру. Заявка включает встречу,
на которой игроки соберутся. Другие пользователи присоединяются к заявке.
В заявке не может быть больше участников, чем нужно по заявке. Один игрок
не может дважды присоединиться к одной заявке. Отменённое участие
освобождает место, но остаётся в истории.

## Основные сущности (классы)

### Game — игра (`models/games.py`)
- атрибуты: `id`, `title`, `min_players`, `max_players`;
- методы: `supports_players()` — подходит ли игра для указанного числа
  игроков; `from_data()` (`@classmethod`) — создание из данных JSON;
  `__str__()`.

### User — игрок (`models/users.py`)
- атрибуты: `id`, `name`, `city`;
- методы: `from_data()` (`@classmethod`), `__str__()`.

### Meeting — встреча (`models/meetings.py`)
- атрибуты: `meeting_date`, `city`, `place`;
- методы: `from_data()` (`@classmethod`), `__str__()`.

### GameRequest — заявка (`models/game_requests.py`)
- атрибуты: `id`, `game` (объект `Game`), `author` (объект `User`),
  `players_needed`, `meeting` (объект `Meeting`), `players_joined`;
- методы: `free_slots()` — количество свободных мест, `add_player()`,
  `remove_player()`, `__str__()`;
- свойства (`@property`): `players_joined` (только чтение), `is_open`.

### Join — участие игрока в заявке (`models/joins.py`)
- атрибуты: `id`, `request` (объект `GameRequest`), `user` (объект `User`),
  `is_cancelled`;
- методы: `cancel()` — отмена участия, `__str__()`.

## Взаимодействие объектов

```text
GameRequest
├── game    → Game
├── author  → User
└── meeting → Meeting   (встреча входит в заявку)

Join
├── request → GameRequest
└── user    → User
```

`Join` хранит ссылки на сами объекты, поэтому данные доступны напрямую:
`join.request.game.title`, `join.user.name`, `request.meeting.place`.
При записи игрока в заявку `create_join()` вызывает `request.add_player()`,
при отмене `join.cancel()` вызывает `request.remove_player()`.

## Возможности

- просмотр, поиск (по игре или городу), отбор и сортировка заявок;
- статистика по заявкам;
- создание заявки с проверкой, подходит ли игра для такого числа игроков;
- присоединение к заявке и отмена участия;
- просмотр каталога игр;
- просмотр, добавление и поиск игроков;
- сохранение данных между запусками.

## Хранение данных

Данные хранятся в JSON в каталоге `data/`. При загрузке они превращаются
в объекты, при сохранении — обратно в словари. Вместо связанных объектов
в JSON записываются их идентификаторы (`game_id`, `author_id`,
`request_id`, `user_id`), а встреча хранится вложенным объектом внутри
заявки:

```json
{
  "id": 1,
  "game_id": 1,
  "author_id": 1,
  "players_needed": 4,
  "players_joined": 2,
  "meeting": {"date": "2026-10-10", "city": "Москва", "place": "Антикафе на Арбате"}
}
```
