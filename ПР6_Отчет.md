## 4. Доработка индивидуального проекта

**Структура шаблонов.** В `settings.py` в `TEMPLATES["DIRS"]` добавлен
каталог шаблонов уровня проекта, шаблоны приложений лежат в их
каталогах `templates/<приложение>/`:

```text
templates/base.html, templates/includes/navigation.html
homepage/templates/homepage/index.html, 404.html
games/templates/games/game_list.html, game_detail.html, includes/game_card.html
gamerequests/templates/gamerequests/request_list.html, request_detail.html,
    includes/request_status.html
```

**Базовый шаблон.** `templates/base.html` содержит общую структуру всех
страниц: объявление документа, кодировку, Bootstrap, собственный CSS,
шапку с логотипом и навигацией, контейнер `main`, подвал и подключение
JavaScript. Дочерние страницы переопределяют блоки
`{% block title %}` и `{% block content %}`.

**Наследование.** Все страницы, включая страницу 404, начинаются с
`{% extends "base.html" %}` и не дублируют общую HTML-структуру.

**Include.** Навигация вынесена в `includes/navigation.html`, карточка
игры — в `games/includes/game_card.html`, бейдж статуса заявки — в
`gamerequests/includes/request_status.html`. Статус заявки используется в
трёх местах: в списке заявок, на странице заявки и на странице игры.

**Передача данных через контекст.** view-функции загружают объекты через
`storage.py` и передают их в `render()`, например
`{"games": games_list}`, `{"game_request": game_request, "players": players}`.
Для заявок использованы имена `game_request` и `game_requests`, чтобы не
перекрыть переменную `request` (HTTP-запрос). Функция `page()` из ПР5
удалена, `HttpResponse(page(...))` больше нигде не используется.

**Циклы и условия.** Списки выводятся через `{% for %}` с `{% empty %}`
для пустых коллекций. Через `{% if %}` выводятся статус заявки
(открыта / закрыта) и сообщения «Игра не найдена», «Заявка не найдена»;
при этом view возвращает `render(..., status=404)`.

**Именованные URL.** В `urls.py` приложений заданы `app_name`
(`homepage`, `games`, `gamerequests`) и имена маршрутов `index`, `list`,
`detail`. Все ссылки в шаблонах формируются через `{% url %}`, например
`{% url 'games:detail' game.id %}`; жёстко заданных адресов нет.

**Фильтры.**
- `length` — количество игр, заявок и участников;
- `default` — название игры (`"Без названия"`) и место встречи
  (`"место уточняется"`);
- `date:"d.m.Y"` — форматирование даты встречи (объект `date`).

**Статические файлы** (`homepage/static/homepage/`), подключены через
`{% load static %}` и `{% static %}`:
- `css/style.css` — собственное оформление шапки, навигации, карточек
  игр и заявок, бейджа статуса и подвала (вместе с Bootstrap);
- `js/main.js` — вывод текущего года в подвале и подсветка активного
  пункта меню;
- `img/logo.svg` — логотип в шапке сайта.

## 5. Результат работы

Переведены на шаблоны все страницы веб-интерфейса:

| URL | Шаблон |
|---|---|
| `/` | `homepage/index.html` |
| `/games/` | `games/game_list.html` + `games/includes/game_card.html` |
| `/games/<id>/` | `games/game_detail.html` |
| `/requests/` | `gamerequests/request_list.html` |
| `/requests/<id>/` | `gamerequests/request_detail.html` |
| несуществующий адрес | `homepage/404.html` |

Основные изменения веб-интерфейса: HTML вынесен из Python в шаблоны,
появились общая шапка с логотипом и подсвечиваемым меню, подвал, карточки
игр, список открытых заявок на странице игры и список участников на
странице заявки. Данные по-прежнему загружаются из JSON через объекты
ПР3, Django ORM и формы пока не используются. README.md обновлён:
описаны шаблоны, возможности DTL, URL с пространствами имён и статика.

## 8. Вывод

В ходе ПР6 веб-интерфейс проекта переведён на стандартную для Django
схему «view → context → template → HTML». Общая структура страниц
вынесена в базовый шаблон, повторяющиеся фрагменты — во включаемые
шаблоны, ссылки строятся по именам маршрутов, а оформление и клиентское
поведение подключены как собственные статические файлы. Предметная
модель и JSON-хранилище сохранены, функциональность ПР3–ПР5 не нарушена,
что подтверждено тестами. Проект готов к переходу на базу данных и
Django ORM.
