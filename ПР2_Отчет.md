## 2. Индивидуальный проект

- **Название проекта:** Сервис поиска игроков для настольных игр
  (`boardgame-finder`)
- **Развитие относительно ПР1:** начальный сценарий ПР1 (одиночные
  переменные `game_title`, `city`, `players_needed`, `players_joined`,
  функция `get_request_status()`) переработан в полноценную программу,
  работающую с множеством заявок и присоединений. Функции
  `get_request_status()` и `calculate_free_slots()` перенесены из ПР1 без
  изменения логики.
- **Структура данных:** заявки — словарь `requests: dict[int, dict]`
  (аналог `rooms`), присоединения игроков — список `joins: list[dict]`
  (аналог `bookings`).
- **Реализованные функции:**
  - `game_requests.py` — `add_request`, `find_request`,
    `calculate_free_slots`, `filter_requests_by_free_slots` (генератор),
    `sort_requests` (сортировка с lambda-ключом), `get_statistics`;
  - `joins.py` — `can_join_request`, `create_join`, `cancel_join`,
    `get_request_status` (из ПР1);
  - `storage.py` — `load_requests`/`save_requests`,
    `load_joins`/`save_joins` — чтение и запись JSON через контекстный
    менеджер `with`, обработка `FileNotFoundError` и `JSONDecodeError`;
  - `utils.py` — `input_int`, `input_date` — безопасный ввод с повтором
    запроса при `ValueError`;
  - `main.py` — точка входа, меню приложения, функции вывода
    (`show_requests`, `show_joins`, `show_statistics`) и обработчики
    пунктов меню (`handle_find`, `handle_filter`, `handle_create_request`,
    `handle_join`, `handle_cancel_join`), диспетчеризация через словарь
    команд.
- **Структура проекта:** `main.py`, `game_requests.py`, `joins.py`,
  `storage.py`, `utils.py`, `data/requests.json`, `data/joins.json`,
  `tests/test_game_requests.py`, `tests/test_joins.py`, `conftest.py`,
  `README.md`, `requirements.txt`.
- **Формат хранения данных:** JSON-файлы в каталоге `data/`; заявка
  хранит `id`, `game_title`, `city`, `players_needed`, `players_joined`,
  `meeting_date`, `is_open`; присоединение — `id`, `request_id`,
  `player_name`.
- **Ссылка на Git-репозиторий:** https://github.com/talovns/django

## 3. Обработка исключений

Некорректный ввод пользователя (нечисловое значение, некорректная дата)
обрабатывается функциями `input_int()` и `input_date()` модуля
`utils.py` — при ошибке `ValueError` запрос повторяется, программа не
завершается аварийно. Отсутствие файла данных и повреждённый JSON
обрабатываются в `storage.py` (`FileNotFoundError`,
`json.JSONDecodeError`) — при ошибке возвращается пустая коллекция вместо
аварийного завершения. Попытка присоединиться к недоступной заявке
обрабатывается через `ValueError`, перехватываемый в `main.py`.
